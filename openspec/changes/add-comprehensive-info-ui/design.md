## Context

当前首页通过 `PrimaryNav` 渲染十个主导航项，但只有“交易大厅”配置了路由行为；路由表目前包含首页与交易大厅。项目已经有可复用的 `SiteHeader`、`ComingSoon`、`BackToTop` 和全局桌面内容容器，因此本次变更只需要在现有 Vue 单页应用内补齐综合信息页面与主导航当前态。行为边界见 `proposal.md` 与 `specs/comprehensive-info-ui/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用现有站点骨架构建独立的综合信息路由，保持首页与交易大厅既有行为不回归。
- 将参考截图中的面包屑、两栏结构、八栏目导航和查询表单拆成可测试的本地状态。
- 复用统一占位和顶部按钮，确保栏目与查询交互永远不会产生真实信息结果。
- 在 1366、1440 和 1920 像素宽桌面视口完成视觉核对。

**Non-Goals:**

- 不接入文章列表、文章详情、分页、数量、搜索、日期过滤或任何 API。
- 不复制原站 HTML、图片、字体文件或脚本，不引入新的 UI、日期或图标依赖。
- 不实现移动端重排，不实现除“综合信息”和既有“交易大厅”外的其他主导航页面。
- 不新增底部“关于我们”“监督投诉”或其他页脚信息块。

## Decisions

### 1. 综合信息使用独立路由并复用首页模式头部

新增 `ComprehensiveInfoView` 并注册命名路由 `comprehensive-info`。视图复用 `SiteHeader` 的首页模式和 `PrimaryNav`，不扩展交易大厅专属头部模式。相较在首页内以条件分支替换正文，独立路由能保持浏览器前进后退语义，也方便后续接入文章详情而不污染首页状态。

### 2. 主导航当前态由路由驱动

`PrimaryNav` 使用结构化导航配置保存标签与可选目标路由，并从当前命名路由推导激活项：首页激活“首页”，综合信息页激活“综合信息”；“交易大厅”继续保持既有跳转和橙色突出样式，其余未实现项仍不跳转。相较由各页面传入数字下标，路由驱动能避免刷新后当前态丢失，也减少页面间重复配置。

### 3. 右侧栏目与表单只维护组件本地状态

八个栏目以固定配置数组渲染，`activeCategory` 默认指向“工作动态”；点击只更新激活样式。日期与关键字使用本地响应式值，表单提交只阻止浏览器默认动作。状态不写入路由查询参数、不持久化、不触发事件给父级，也不调用请求层，从结构上保证左侧结果不变。

### 4. 左侧复用统一 ComingSoon 并由页面控制占位高度

综合信息左栏直接复用现有 `ComingSoon`，外层结果面板负责匹配截图所需的最小高度与垂直居中。相较复制占位 DOM，这能保持交易大厅与综合信息的法槌、双语文案和颜色一致；页面级包装避免修改共享组件而导致交易大厅回归。

### 5. 图标使用本地 CSS 或字符结构

面包屑定位图标、栏目圆点、右箭头和日期图标使用 CSS/内联本地结构表达，不下载原站图标或增加图标包。验收重点是颜色、大小、位置和清晰度，而不是复刻原站位图资源。

### 6. 视觉样式局部封装并沿用站点容器

正文使用既有 `site-container` 宽度，在内部建立左侧弹性列与约 300 像素右侧栏。页面样式封装在视图/侧栏组件中，以截图的红、黄、米白、浅灰色值为基准；仅在窄桌面断点压缩间距，不改成移动端单列。浏览器核对以 1366、1440、1920 三个宽度为基准。

## Risks / Trade-offs

- [“可选择但无查询结果”可能被误认为功能失效] → 栏目保留明确激活反馈，输入值保留，但左侧始终显示统一“敬请期待”，自动化测试同时断言无请求与无内容变化。
- [修改共享主导航可能影响首页或交易大厅入口] → 用首页、综合信息、交易大厅三条路由的端到端断言覆盖激活态与跳转行为，并保留其余导航无响应测试。
- [原生日期输入在不同浏览器外观存在细微差异] → 以固定外框、图标、字体和布局包裹控件，验收以 Chromium 视觉为主，不引入额外日期组件。
- [复用 ComingSoon 时页面高度不足] → 由综合信息结果容器提供稳定最小高度，避免改变共享组件本身。
- [桌面容器在 1366 像素下右栏挤压左栏] → 固定右栏合理宽度、左栏使用 `minmax(0, 1fr)`，并以多视口截图和无横向溢出断言校验。

## Migration Plan

1. 将主导航数据结构化并补充基于当前路由的激活态，先运行首页与交易大厅回归测试。
2. 新增综合信息路由、视图和右侧栏目/筛选结构，接入共享头部、占位与顶部按钮。
3. 补齐行为测试和无外部请求断言，再在三个桌面视口进行浏览器视觉精调。
4. 生产构建验证通过后发布；如需回滚，只需移除综合信息路由与入口映射并恢复原主导航当前态逻辑，不影响既有页面数据。
