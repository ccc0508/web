## Context

当前 Vue 3 + Vue Router 门户已经具备首页、综合信息、交易动态和交易大厅页面，并已有稳定尺寸的 `PrimaryNav`、站点头部、`CompactFilterOptionGroup`、`ComingSoon` 与 `BackToTop`。交易动态页面已建立紧凑筛选面板和可展开附加筛选的本地状态模式，但临期资产具有独立的到期期限默认值、不同筛选组和仅含关键字的更多选项。详见 `proposal.md` 和 `specs/expiring-assets-ui/spec.md`。

约束包括：只复刻可见界面及演示交互；不请求原站或后端；不导入资产数据；结果始终为敬请期待；桌面端重点匹配 1366、1440 和 1920 像素宽视口。

## Goals / Non-Goals

**Goals:**

- 在不破坏现有普通主导航尺寸稳定性的前提下接入临期资产本地路由。
- 复用已经验证的紧凑筛选交互模式，同时保持临期资产配置、默认值和展开状态独立。
- 用声明式配置固定截图中的选项内容与顺序，便于测试精确校验。
- 让基础筛选、关键字确认与全部撤销拥有清晰、可访问、无副作用的本地反馈。
- 通过桌面端端到端与视觉检查保证收起、展开两种布局接近参考截图。

**Non-Goals:**

- 不接入资产查询、数量、列表、排序、分页、图片或详情页。
- 不实现区与镇街联动，不因筛选选择裁剪任何选项。
- 不同步 URL 查询参数，不持久化筛选状态，不新增运行时依赖。
- 不加载或嵌入原站资源，也不实现当前需求之外的主导航页面。

## Decisions

### 1. 使用独立视图和独立筛选面板，复用现有基础展示组件

新增 `ExpiringAssetsView` 与 `ExpiringAssetsFilterPanel`，视图复用 `SiteHeader`、`PrimaryNav`、`ComingSoon`、`BackToTop`，筛选行优先复用 `CompactFilterOptionGroup`。这样既延续已验证的字体、间距和红色选中态，又避免把临期资产语义塞入交易动态组件。

备选方案是直接给 `TransactionDynamicsFilterPanel` 增加模式参数。该方案会让两类页面的默认值、基础组和更多选项产生大量条件分支，降低后续精调与测试可读性，因此不采用。

### 2. 以独立配置模块固化选项和默认状态

新增临期资产配置模块，定义类型化状态、区、镇街、到期期限和资产类别数组，以及默认状态工厂。页面只从该配置渲染，测试可直接按规定顺序断言，全部撤销也使用同一默认工厂避免状态漂移。

备选方案是在模板中手写选项。该方案更容易出现顺序遗漏、默认值重复和后续维护不一致，因此不采用。

### 3. 基础筛选采用本地单选状态，已选条件只呈现非默认值

每组以单一字符串维护当前值。派生的已选条件列表将状态与默认状态比较，只输出非默认基础值与已确认关键字。所有按钮使用本地事件更新，不调用路由、fetch 或任何业务服务。

这与截图中默认选中项存在但“已选条件”为空的语义一致，并能让“全部撤销”一次恢复到规定初始态。

### 4. 更多选项使用显式展开状态和两阶段关键字状态

使用独立布尔值控制关键字行显示，并让按钮同步箭头、`aria-expanded` 与关联区域。关键字分别维护输入值和已确认值：输入不会立即形成已选条件，点击“确定”后才确认；收起不清除二者，全部撤销同时清空二者但不强制改变展开状态。

备选方案是输入即生效。该方案无法体现原站的“确定”入口，也使撤销和测试语义含糊，因此不采用。

### 5. 结果区直接复用统一 ComingSoon，避免任何条件渲染

结果容器始终渲染现有 `ComingSoon`，不根据筛选状态分支，也不创建空列表、数量、排序或分页模型。这从结构上保证交互不会意外显示数据或“暂无公开数据”。

### 6. 路由名驱动主导航激活态

在 Router 中注册 `/expiring-assets` 命名路由，在 `PrimaryNav` 中只为“临期资产”补充相应 `routeName`。继续使用既有基于路由名的激活判断，避免页面自行注入 active class，从而继承已修复的普通导航尺寸稳定规则。

## Risks / Trade-offs

- [大量镇街与资产选项在不同宽度下换行不一致] → 沿用紧凑选项组并为临期资产面板设置经过 1366、1440、1920 视口验证的标签列宽、间距和换行规则。
- [展开关键字行后底部按钮可能覆盖内容或结果区] → 让展开内容参与正常文档流，按钮定位相对面板的新底边，并对收起与展开两种高度分别做视觉检查。
- [复用组件样式改动可能回归交易动态页面] → 优先通过临期资产容器作用域样式覆盖；端到端回归继续执行全部现有页面测试。
- [“全部撤销”误改展开状态] → 将筛选值重置与 `isMoreExpanded` 分离，测试明确验证展开状态保持不变。
- [筛选按钮被误实现为真实查询入口] → 组件不注入服务依赖，端到端监测无业务/原站请求且结果始终为 ComingSoon。

## Migration Plan

1. 增加临期资产配置、筛选面板与视图，不修改已有页面数据结构。
2. 注册新路由并为现有主导航项补充路由目标。
3. 增加临期资产端到端测试并运行现有全部回归测试、类型检查与生产构建。
4. 在规定桌面视口检查收起和展开状态，再提交发布。

回滚时移除新路由、主导航目标和新增临期资产文件即可；该变更无数据库、接口或持久化迁移。
