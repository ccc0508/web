## Context

现有 `/trade-hall` 页面已经具备品牌头部、展示型搜索、五项二级导航和空白内容区。第二阶段需要在不接入后端的前提下加入原站交易大厅的完整静态结构与本地交互；六种交易模式大部分筛选相同，但公开协商和定价招租存在可见差异。参见 `proposal.md` 与 `specs/trade-platform-ui/spec.md`。

## Goals / Non-Goals

**Goals:**

- 通过配置复用共同筛选结构，同时准确表达三类模式差异。
- 让所有页签、筛选项、清除/收起和顶部按钮具备可测试的本地交互。
- 用统一占位状态保证任何选择都不会误导用户认为已有真实项目数据。
- 延续交易大厅第一版的本地资源、桌面端宽度和视觉体系。

**Non-Goals:**

- 不实现筛选查询、排序、分页、项目详情、报名、竞投、保证金、会员和协议正文。
- 不实现二维码、扫码入口、登录注册或外部跳转。
- 不引入后端、持久化、地图、日期库或新的 UI 依赖。

## Decisions

### 1. 使用模式配置驱动一个筛选面板

六种模式使用统一的模式配置，包含显示名称、类别选项、状态标签、状态选项以及可选的“协商方式”。所属区、资产类别、价格、时间、发布日期和关键字作为公共配置复用。相比复制六套模板，这能避免选项顺序和样式漂移，同时允许公开协商与定价招租精确覆盖差异。

### 2. 所有状态保留在交易大厅视图内

二级导航激活项、当前交易模式、每组筛选值、输入值和折叠状态都使用页面本地状态。二级导航不新增会员或协议路由，因为这些页面只有同一“敬请期待”占位；右侧智慧云平台链接仍使用现有首页路由。相比创建多个空路由，本地视图切换更符合本阶段范围且更容易保证无副作用。

### 3. 切换交易模式时载入该模式默认筛选

每次切换模式，筛选组恢复默认“不限”，输入框清空，已选条件清空。该行为保持演示状态清晰，也接近原站切换交易类型后重新查询的交互；不在模式之间持久化筛选，避免用户误认为筛选可以跨交易机制生效。

### 4. 结果区统一使用可复用敬请期待组件

交易结果和四个辅助导航页面共用同一占位组件，使用 CSS 绘制或本地矢量图形表现浅灰法槌，不引用原站图片。该组件固定包含“敬请期待...”与“Coming soon...”，不复用首页的“暂无公开数据”，以严格匹配本次截图。

### 5. 筛选控件模拟原站但不触发数据逻辑

普通选项使用单选按钮语义，自定义金额、日期和关键字使用本地表单控件；“确定”只保留输入状态。“已选条件”显示非默认选择，“清除”恢复默认，“收起/展开”切换可见性。排序控件按原站当前灰色禁用状态显示“默认排序”。

### 6. 竞投流程使用本地 CSS 图形与文字

八个步骤使用圆形粉红图标、橙红箭头和两行文字构成，不复制原站位图。可使用简化线性符号或文字图标，但圆形尺寸、节奏、颜色和步骤顺序必须按截图核对。这样同时满足本地资源约束和视觉接近度要求。

### 7. 返回顶部按钮提取为共享组件

将首页现有固定按钮提取为可复用组件，首页与交易平台共用尺寸、颜色、箭头和滚动逻辑。相比在交易大厅复制样式，共享组件可以防止后续两处视觉不一致；首页外观和现有测试必须保持不变。

## Risks / Trade-offs

- [筛选选项数量大，容易在较窄桌面宽度换行错位] → 使用原站式多行弹性布局，并在 1366、1440、1920 像素视口逐档截图核对。
- [模式配置遗漏差异] → 用端到端测试分别断言公共竞投、公开协商和定价招租三类配置，并核对六个模式都能切换。
- [可点击筛选可能让用户误以为存在真实查询] → 结果始终显示“敬请期待”，排序保持禁用，并监听测试确保没有接口请求。
- [提取首页顶部按钮可能引入首页回归] → 先保留原 DOM 与样式合同，再以首页和交易平台双页面测试验证。
- [日期输入的原生控件外观因浏览器而异] → 以布局和可输入性为验收重点，不引入日期组件依赖。

## Migration Plan

1. 提取并回归验证共享返回顶部按钮。
2. 新增竞投流程与统一敬请期待组件。
3. 建立六种模式配置和筛选面板本地状态。
4. 将二级导航改为本地可切换内容视图，并确保右侧返回首页行为不变。
5. 补充自动化测试和多视口视觉核对后上线；若需回滚，可恢复第一版空白内容区而不影响现有首页和路由。
