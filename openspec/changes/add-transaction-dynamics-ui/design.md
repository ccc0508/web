## Context

当前主导航已经使用路由名称驱动首页与综合信息激活态，但“交易动态”仍没有目标路由。项目已有 `SiteHeader`、`PrimaryNav`、`ComingSoon`、`BackToTop` 和交易大厅筛选配置；参考截图中的交易动态筛选更紧凑，并新增完整镇街清单、已选条件区和底边“更多选项”入口。具体行为边界见 `proposal.md` 和 `specs/transaction-dynamics-ui/spec.md`。

## Goals / Non-Goals

**Goals:**

- 复用门户骨架建立独立交易动态路由，并保持首页、综合信息、交易大厅现有行为不回归。
- 以可配置数据准确表达五组筛选的完整文案、顺序、默认值和紧凑换行。
- 提供可测试的本地单选、已选条件与全部撤销交互，同时保证结果始终为统一占位。
- 在 1366、1440 和 1920 像素桌面视口完成截图级视觉核对。

**Non-Goals:**

- 不实现真实筛选、区镇联动、公告查询、排序、分页或详情跳转。
- 不实现“更多选项”展开内容；成交金额、发布日期和关键字只保留在按钮文案中。
- 不引入远程资源、原站代码、后端接口、图标包或新的运行时依赖。
- 不实现移动端单列页面，也不新增底部信息块。

## Decisions

### 1. 交易动态使用独立路由与共享门户骨架

新增 `TransactionDynamicsView` 并注册命名路由 `transaction-dynamics`。视图复用首页模式 `SiteHeader`、`PrimaryNav`、`ComingSoon` 和 `BackToTop`。相较在首页内条件渲染，独立路由能保留刷新、前进后退与当前导航态，并为后续真实公告列表预留清晰边界。

### 2. 使用专用配置保存筛选文案与默认值

新增交易动态配置，分别定义区、镇街、资产类别、交易模式、公告类型及默认状态。资产类别虽然与交易大厅高度相似，但交易动态截图使用不同的括号、空格和换行密度，因此保持专用展示数组，避免修改交易大厅已验收文案。配置使用只读字面量，状态类型由配置推导。

### 3. 使用专用紧凑筛选组而非直接复用交易大厅组件

交易大厅 `FilterOptionGroup` 的标签宽度、选项最小宽度和行高针对 1160 像素竞投面板设计，不符合本截图中约 100 像素标签列和按文字长度流动的密集排版。交易动态实现专用筛选组或在页面组件中封装统一行结构，复用单选语义但使用独立样式，从而避免影响交易大厅回归。

### 4. 五组状态集中在筛选面板本地管理

筛选面板使用一个本地响应式状态对象保存五组当前值。每组点击只替换自身值；计算属性从当前值与默认状态的差异生成已选条件标签。“全部撤销”用默认工厂整体恢复。状态不提升到路由、不写查询参数、不持久化，也不触发请求。

### 5. 公告类型默认值作为基线而非额外已选条件

虽然公告类型默认“交易公告”而非“不限”，已选条件区域仍以各组默认值作为基线，因此初始截图保持空白；只有切换到结果公示、成交公告、终止公告或失败公告才显示公告类型标签。这与截图的空“已选条件”及红色“交易公告”同时存在相符。

### 6. 更多选项入口固定为无副作用收起状态

按钮按截图以绝对/负边距方式贴合面板底边中部，并带向下箭头。点击只阻止默认行为，不改变 `aria-expanded=false`、不渲染附加行。相较猜测未提供的展开面板，本方案严格限制在用户给出的截图范围内。

### 7. 面包屑按截图文案保留“结果公示”

尽管主导航页面名为“交易动态”，正文面包屑仍固定显示截图中的“首页 / 结果公示”；筛选公告类型的本地切换不修改面包屑。该选择优先满足用户要求的截图一致性，并避免无数据页面产生动态页面语义。

## Risks / Trade-offs

- [镇街选项多，桌面窄宽度容易产生不一致换行] → 选项按内容宽度流动、标签列固定，并在三个验收视口逐档截图核对。
- [可点击筛选可能让用户误认为真实查询已接入] → 结果区始终显示“敬请期待”，自动化测试监听并断言无原站或业务请求。
- [独立资产类别数组可能与交易大厅产生文案漂移] → 仅在交易动态配置中维护截图要求的显示文本，并用顺序测试锁定；不共享样式和默认状态。
- [共享主导航改动可能影响现有页面] → 更新首页导航回归测试，并在首页、综合信息、交易动态和交易大厅之间验证激活态与跳转。
- [更多选项看似可操作但不展开] → 保留明显的收起态 `aria-expanded=false`，并在规范中明确本期范围；后续获得展开截图后再单独扩展。

## Migration Plan

1. 新增交易动态配置和紧凑筛选组，并以组件测试/端到端断言锁定完整选项顺序。
2. 新增交易动态视图和路由，再将主导航“交易动态”映射到该路由。
3. 接入已选条件、全部撤销、固定更多选项与敬请期待结果区。
4. 运行现有全量回归测试，并完成三个桌面视口视觉精调后发布。
5. 如需回滚，移除路由与交易动态入口映射即可恢复原无响应行为，不影响其他页面。
